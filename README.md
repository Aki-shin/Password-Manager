# Password Manager

Минималистичный веб-менеджер паролей для системных администраторов.
Хранит учётки серверов, сетевого оборудования, рабочих станций и сервисных
аккаунтов в одной зашифрованной SQLite-базе.

Изначально спроектирован для работы за **Lab Manager** (прозрачный TCP-прокси
с авторизацией) — приложение слушает только `127.0.0.1`, авторизация и TLS
снимаются на уровне прокси. Локально запускается так же.

## Возможности

- Категории: инфраструктура, серверы, сетевое оборудование, рабочие станции,
  сервисные аккаунты, прочее.
- Поля под сисадминские задачи: хост/IP, порт, протокол (ssh/rdp/winrm/…),
  логин, пароль, URL, теги, повышение привилегий (sudo/su) с отдельным паролем.
- Поиск по названию, хосту, логину, тегам, URL + фильтр по категории.
- Симметричное шифрование паролей и заметок (Fernet / AES-128-CBC + HMAC).
- Заметки и пароли по умолчанию замаскированы — раскрываются по кнопке.
  Раскрытый секрет автоматически скрывается через 30 секунд.
- Копирование в буфер обмена; буфер автоматически очищается через 30 секунд.
- **Журнал доступа** (`/audit`) — кто, когда и с какого IP создавал,
  редактировал, удалял записи и смотрел/копировал пароли.
- **Светлая и тёмная тема** — переключатель в шапке, выбор хранится в cookie.
- Бэкап и восстановление в один клик (zip с `vault.db` + `master.key`).
- Без внешних зависимостей кроме Flask, SQLAlchemy и `cryptography`.

## Безопасность

- CSRF-токен на всех POST-формах (создание, редактирование, удаление,
  восстановление бэкапа).
- Строгий **Content-Security-Policy** (`default-src 'self'`, без
  `unsafe-inline`), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer`.
- Session cookie — `HttpOnly` + `SameSite=Lax`.
- API получения секретов отдаёт только запрошенное поле и пишет событие
  в журнал доступа.

## Стек

- Python 3.10+
- Flask 3 + Flask-SQLAlchemy 3
- SQLite (через SQLAlchemy)
- cryptography (Fernet)
- Без сборки фронтенда: чистый HTML + один CSS + один JS.

## Установка и запуск

```bash
git clone https://github.com/Aki-shin/Password-Manager.git
cd Password-Manager

python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt

# Запуск (PORT обязателен):
PORT=8000 python app.py
```

Откройте `http://127.0.0.1:8000`.

### Переменные окружения

| Имя          | Обяз. | Назначение                                                       |
| ------------ | ----- | ---------------------------------------------------------------- |
| `PORT`       | да    | Порт для прослушивания.                                          |
| `HOST`       | нет   | Интерфейс (по умолчанию `127.0.0.1`).                            |
| `SECRET_KEY` | нет   | Flask secret для сессий. Если не задан — генерируется случайный. |

### Запуск за Lab Manager / обратным прокси

Приложение размещено на корне (`/`), без префикса пути.
Авторизацию и TLS вешайте на уровне прокси. CSRF/cookie-сессии Flask
работают как обычно — не забудьте задать фиксированный `SECRET_KEY`,
если хотите, чтобы сессии переживали рестарт.

## Данные и шифрование

При первом запуске в `instance/` создаются два файла:

- `vault.db` — SQLite с записями. Пароли и заметки хранятся уже
  зашифрованными.
- `master.key` — ключ Fernet. **Без него базу расшифровать невозможно.**

Папка `instance/` исключена из git (см. `.gitignore`).

### Бэкап

Кнопка «Бэкап» в шапке скачивает zip с `vault.db` и `master.key`.
Храните бэкапы отдельно от исходного хоста — компрометация бэкапа
эквивалентна компрометации всех паролей.

### Восстановление

Кнопка «Импорт» загружает zip обратно. Перед заменой текущие файлы
копируются в `instance/*.pre-restore-<timestamp>`. Если импорт упадёт —
автоматический откат.

## Модель угроз и ограничения

- **Авторизация — снаружи.** Приложение не реализует логин/пароль
  пользователей. Доступ к URL = полный доступ ко всем записям.
  Поднимайте за прокси с авторизацией (Lab Manager, nginx + basic auth,
  oauth2-proxy и т.п.).
- **HTTPS — снаружи.** Приложение слушает только `127.0.0.1`. TLS
  делается на проксе.
- **Никакого аудит-лога.** Кто и когда смотрел пароль — не пишется.
- **Однопользовательский режим.** Один общий ключ, общий набор записей.
- **Не запускайте `debug=True`.** В коде явно `debug=False` —
  не меняйте без причины.
